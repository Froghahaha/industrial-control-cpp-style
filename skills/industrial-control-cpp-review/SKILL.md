# 工控 C++ Diff Review

这是一次性、diff 范围内的专项审查。先阅读变更涉及的调用链和契约，再输出最小可执行的问题清单；不要把个人偏好写成硬错误。

## 审查顺序

1. 输入责任是否放在正确边界，是否重复校验或擅自修正；
2. 主流程是否仍然连续，安全门和唯一提交点是否可见；
3. 所有权、线程阶段和控制周期资源行为是否明确；
4. 失败是否区分拒绝、不可用、故障和安全抑制；
5. 顶层是否能定位模块、阶段、操作和原始根因；
6. 注释是否记录契约而不是逐行复述。

审查 guard、fallback、catch、默认值或重试时，按“真实风险、责任边界、失败分类、是否继续、顶层可见性”判断。旧值/零值 fallback、吞异常后继续、未知状态按正常处理、无界重试和发布先于提交，默认视为高风险；有明确业务策略、状态投影、退出条件和测试时才允许例外。

## 输出格式

每条问题一行：

```text
<file>:<line>: <tag> <问题和真实风险>. 最小替代方案.
```

标签使用：`contract`、`flow`、`commit`、`ownership`、`realtime`、`fault`、`fallback`、`comment`、`over-split`。

只报告可定位且会影响行为、维护或诊断的问题。没有问题时输出：`Lean and diagnosable. Ship.`

不要在该 skill 中直接编辑文件；用户若要求修复，再回到核心 skill 执行修改和验证。
