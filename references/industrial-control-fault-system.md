# 工控契约与故障体系

本文件是故障设计的按需专题。它独立于任何具体仓库、硬件品牌或协议。

## 输入责任矩阵

| 边界 | 负责确认 | 下游默认可信任 |
| --- | --- | --- |
| 传输 | 帧完整性、长度、版本、序列 | 收到的是完整传输帧 |
| 协议 | 消息类型、字段组合、编码 | 收到的是合法消息 |
| 业务 | 状态、权限、单位、范围、容量 | 收到的是可进入该业务的输入 |
| 算法内部 | 算法前提、维度、数值不变量 | 输入满足算法前提 |

每个模块只校验自己拥有的业务语义。上游已明确完成的检查不在下游重复实现；下游拥有的不变量不能因为“上游应该检查过”而省略。发现不属于本模块职责的问题时，报告并停止当前流程，不要改成默认值。

## 失败分类

```text
正常拒绝          调用者可修正的公开输入问题
外部不可用        硬件、连接、服务或资源暂时不可用
安全抑制          策略主动禁止输出，但系统仍处于可解释状态
内部不变量破坏    按契约不应发生的状态或数据
配置/初始化失败   无法建立基本运行条件
已接受操作失败    已接受动作在执行中失败
```

默认处置：正常拒绝返回明确结果；外部不可用进入可见的 unavailable/degraded 状态；安全抑制发布明确 inhibited/safe 状态；内部不变量硬失败并停止依赖链；配置失败不创建半有效对象；操作失败发布带上下文的失败事件。

## Fallback 和重试

Fallback 只有在它是事先定义的业务策略时才存在。必须同时写清触发条件、替代路径、对外状态、退出/恢复条件和测试。用上一帧假装本帧读取成功、转换失败返回零值、未知状态按正常处理，均属于静默 fallback。

重试同样需要次数或时间上界、终止条件、可观测状态和最终失败路径。没有这些条件时直接失败，不自动重试。

## 故障记录

故障至少保留：

- 模块或故障域；
- 阶段和操作；
- 稳定错误码与严重等级；
- 时间、序列或请求 ID；
- 原始原因和必要上下文；
- 当前状态、输出是否被抑制、是否可恢复。

低层保留根因，上层只补充上下文。故障快照、故障状态或故障事件是正式诊断来源；日志只解释过程，不能成为唯一证据。

## 故障闭环

```text
检测根因
→ 分类故障
→ 停止受影响的业务链
→ 发布安全输出或明确禁止状态
→ 记录上下文并向顶层投影
→ 通过显式 reset/clear/recover 恢复
```

清除故障不能依赖下一次循环自动发生。恢复入口必须定义前置条件；恢复失败仍应保留原故障或新的明确根因。

## 债务标记

暂时无法完整表达契约或故障分类时，用可检索标记记录当前假设、适用范围和升级条件：

```cpp
// industrial-contract: 此层信任上游已完成协议长度校验；本层只检查业务状态。
// industrial-fault-debt: 当前仅区分 transport unavailable；补齐驱动码后拆分恢复策略。
```

标记不是故障处理的替代品。没有升级条件的标记应在债务审查中被列为高风险。
